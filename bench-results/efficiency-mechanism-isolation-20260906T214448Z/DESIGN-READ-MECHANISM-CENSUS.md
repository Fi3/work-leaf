# V3 read-mechanism census

This prospective descriptive derivation covers every frozen workflow and every v3 read boundary in
run-ID/trace-sequence order. It authorizes no provider generation, allocation, replacement, extra
significance endpoint or causal-share estimate. Selection is a complete census, never a cost ranking.
Failure, rejection, no eligible read, missing usage, compaction and unresolved identity remain visible.

## Inputs and existing owners

`analyze_untracked_reads.py::prompt_inventory` owns exact candidate validation, accepted typed RPC
delivery and reverse coverage. The final report's source inventory and accounting records bind its
captured inputs; the census independently replays that pure delivery function and rechecks sources.
`accounting_untracked_reads.py` owns the future-only whole-workflow identity/scope correction. The
census never rewrites its measurements or interprets missing usage as zero.

`audit_input_attribution.py::extract_records` supplies top-level item plus request-field arithmetic,
native response identity checks, signed residuals and safe native metadata. Its source SHA-256 is
`ad6861e834c09f0027305abe223dbe80ae03401740abdae6288580d880bb0740`. Only explicitly selected pure
definitions/constants are loaded from these pinned bytes. Its older compaction-dependent CLI and
cost-ranked summary are not invoked. The census uses the new accounting owner's exact response
inventory rather than a predecessor scope decision.

`build_ack_packet.py` illustrates source endpoint/physical-line safeguards but its v2 ACK inventory
is not converted into v3 read evidence. Existing historical exposure and episode notes are examples,
not rules keyed to their paths, IDs, costs or contents. No old helper or report is edited.

## Output and join rules

The new `audit_read_mechanism.py` and `test_audit_read_mechanism.py` produce one create-new
`READ-MECHANISM-CENSUS.json` and optionally a compact coverage summary after phase closure. The JSON
retains the complete frozen row population. It does not compute condition differences, token rankings,
p-values or a replacement primary. It records its own source identity and every consumed source hash.

Each read record retains trace sequence/physical locator, candidate hashes and byte counts, owned
snapshot body intervals/hashes, successful bundle path, eligibility and selected representation,
plus exact capture, typed RPC, accepted thread/turn and reply locators. Rejected and prepared-but-unsent
boundaries are present and are not accepted exposure.

An accepted selected string joins a native public user-message item by exact verified thread,
explicit accepted turn and byte-equal text when native turn metadata exists. Both direct `turn_id`
and `internal_chat_message_metadata_passthrough.turn_id` are supported and must agree when both
exist. A conflicting explicit turn is not a candidate. Without a matching explicit-turn item, a
unique same-thread byte-equal item lacking explicit turn metadata may be a fallback; multiple such
identities remain ambiguous. One native item cannot serve distinct accepted inputs. Hash indexing
is followed by byte equality. A preceding `turn_context` is never assumed to own a later user
message. The accepted turn's completed responses join directly by explicit thread/turn IDs,
independently of whether that user-item identity resolves.

All completed response IDs and their native/raw locators remain in a single response table. It
includes top-level per-item input/cached/cache-write charges, separately counted request fields,
actual usage, signed reconciliation residuals and unknown states. Read records reference every
observed charge of their uniquely linked native input item, not only the first response. These are
charges of that whole recorded item, including nonfactor framing and mixed read sections; candidate
bytes or snapshot spans are not token allocations. A repeated charge is not repeated execution, and
a same-response input-wrapper charge is not automatically a replay of complete earlier content.

The native public tool inventory retains every call/output identity and physical locator, whether
or not it references a bundle. Calls and outputs join only by exact `(thread_id, call_id)`; missing,
conflicting, duplicate and unknown shapes stay explicit. Exact issued-bundle path references inside
public arguments are located by a linear multi-pattern scanner, with boundary ambiguity retained.
Each reference must follow the corresponding uniquely linked issued input in the same native source;
otherwise its temporal association is unresolved. Unselected candidate text does not make a bundle
path delivered to that agent. Explicit mediated bundle-file reads are a separate read-response class.

An argument path reference with a matching executed tool result is a retrieval **candidate**, not
proof that a file was opened or that the whole result came from that bundle. Generic command/result
semantics require source review before an actual-read claim; compound commands, indirect variables,
directory scans and unknown tools remain limitations. Results preserve byte lengths, public payload
hashes, exact result-item IDs and all recorded input-charge references, not fabricated file-open
counts or content attribution. No automatic claim of no retrieval follows from no explicit match.

## Safety, complexity and tests

The output projects safe type/role/name/call IDs, paths, lengths, hashes and locators. It exports no
message body, tool-argument/result body, private reasoning body or credential value. Source files
are canonical regular files and hash-checked before and after derivation. Closed terminal receipts
and final source provenance are required before publication; reports use create-new output.

Sources are indexed once. Requests, native items, response IDs and charge joins use dictionaries;
multiple path matching is linear in argument bytes plus emitted matches. Each shared response/item
is stored once and referenced by index, avoiding repeated full transcripts or per-read rescans.
Output ordering uses identities/source sequence, never token magnitude. Hard resource limits fail
closed rather than clipping evidence or silently dropping a workflow.

RED-first tests cover exact and ambiguous user-item joins, typed RPC/turn rejection and physical
blank-line mapping, source changes and malformed IDs, top-level/request-field reconciliation without
nested double counting, unchanged unknown residuals/tails, same-thread unique call/output linkage,
bundle references before/after delivery and only in unselected candidate text, indirect/unknown
activity, no body leakage, complete failed/missing-row retention and create-new publication.
Independent review and synthetic or closed-diagnostic replay precede use on study observations.
