## Counting unit and research premise

One task is one named, bounded check with a specific question, finite inputs,
an observation ceiling and a saved result. It is not a catch-all objective such
as "finish attribution" or permission for unlimited sub-experiments.
The table shows all remaining tasks, including causal tests and final analysis.
Five rows are specific intervention screens; the remaining seven are their
design, one bounded confirmation decision/batch, or finite evidence analyses.
The counter is a task count, not a number of independent hypotheses or a time ETA.

The historical ~50% reduction and the user's no-quality-loss assumption are
the premises. Existing normal baselines and the completed standalone run are
reused. No repeat to prove savings exist, new ordinary control, benchmark-error
search or quality study is included. Fresh measurements only account for a
selected causal intervention. Bench-only changes, subscription authentication,
fixed prospective budgets and all-outcome retention remain mandatory.

### Frozen intervention groups

- **A — publication/work-unit and test-timing contract:** buildable implementation
  plus required tests as one cohesive work unit, versus the declared original
  executed-test-first/incremental contract. Required functional work and test
  coverage are not removed.
- **B — real operation-feedback and handoff contract:** accepted-work and check
  results followed by focused next-action/completion/reporting guidance. Actual
  operation success/failure, diagnostics and repair permission remain truthful.
- **C — write/tool custody boundary:** read-only native author inspection plus
  host-owned writes/commits, versus native write/tool availability. The precise
  changes needed to vary C without silently varying A/B are a prerequisite in
  R01; inability to make that contrast is not a positive or negative effect.

R08 is eligible only when a qualified R02–R06 arm actually changes the predicted
input/state → work decision → operation/history chain in the expensive direction,
has a favorable causal information-to-cost rationale, and preserves non-targets.
Select by demonstrated explanatory reach, not the largest unqualified token
number. Freeze the selected arm and comparison before generation. A successful
host or lower/higher total alone is insufficient. The maximum is three workflows
with 90-minute walls and prospectively specified observed-usage tripwires; these
ceilings are not targets. Reuse existing qualification and stop if the method
would exceed the task's declared boundaries.

## Counter and zero rules

1. IDs, questions, scope limits and completion criteria are frozen at approval.
   Reordering by promise is allowed; silently adding, splitting, replacing,
   reopening or broadening tasks is not. No new work hides as an uncounted substep.
2. DONE increases by exactly one and TODO decreases by exactly one only for a
   completed listed check with its saved, dated evidence and honest outcome.
   A supported, unsupported, inconclusive, failed-setup or justified not-needed
   result can finish that finite check; none is automatically a verified cause.
   Starting work, writing a protocol or reaching a timeout without its result
   record does not advance the counter.
3. TODO never increases under agent authority. New necessary work discovered
   before zero is listed as an unapproved scope issue, not executed or smuggled
   into another row. Existing listed work may continue if still meaningful.
4. At TODO=0, stop. If the requested answer is supported, report it. Otherwise
   state **case (1): additional work is needed beyond the declared list**, or
   **case (2): the initial list omitted/miscounted necessary work**. Identify the
   concrete issue and ask permission for the exact added tasks/count. If both
   apply, say both; do not choose a euphemism to hide a planning mistake.
5. An agent cannot grant that permission to itself, reset the scope, or lower
   completion standards. Only an explicit subsequent user approval permits an
   appended scope/count checkpoint. Preserve the zero checkpoint and every
   completed record. No new scope starts while a permission request is pending.
6. The first line and visible task rows derive from one ledger. A separate
   append-only publication history detects rollback and unauthorized task-set
   changes. Its numeric checks do not replace scientific evidence review.

Research is paused after this tracker repair until the user restarts it.
