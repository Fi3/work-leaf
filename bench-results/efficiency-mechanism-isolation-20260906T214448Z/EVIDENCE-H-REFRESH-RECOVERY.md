# H automatic-refresh recovery: complete finite chains

All14 already inventoried changed-file refreshes deliver complete changed-file diffs;
none exercises the48-KiB omission limit, an unavailable diff or the untracked full-text
cap. The cap is therefore not an exercised H saving mechanism in these cases. Compact
delta delivery itself remains a distinct, observed input channel—not a proved net saving.

The [source-bound index](EVIDENCE-H-REFRESH-RECOVERY.json) joins each complete request
to its typed successful reply and exact public user item, then follows the same author
through the next accepted patch ACK. It retains the12 raw-source hashes, complete
input/output hashes, accepted turn and public item IDs, prior snapshot-reference inputs
and intervening same-file ACKs. No provider, accounting replay or new experiment is used.

## What the14 inputs actually represent

at least one later accepted same-file group from another author before the refresh.
This establishes intervening accepted activity; it does not identify the sole cause of
each failed hunk. In particular, three original diagnostics are parser errors about
duplicate file headers, not stale-context applicability failures.

that parser error was caused by concurrency.

## Subsequent actions and limits

Five additional requested-read handoffs occur across four of the nine chains:
003/C49,004/C54,C56,005/C56 and006/C77. Five chains reach their accepted ACK without
another requested-read handoff inside this bounded interval. The index retains each
actual top-level directive, selected target path list and public message identity.
These counts do not assert that native bundle retrieval was absent or that no other
generated response occurred; this check follows the exact public orchestrator handoffs.

Three chains also contain same-snapshot/malformed-edit repair:002/C40,005/C81 and
006/C41,C75. Those events remain in the recovery windows without being recounted as
changed refreshes. Shared suffixes of overlapping refresh windows are represented once
per eventual ACK in `chains`; no repeated transcript is counted as extra work.

The acceptance endpoint is not proof of a byte-identical reconstructed test tree,
unchanged test semantics or a passing final check. This result neither questions the
user's quality working assumption nor upgrades an ACK into validation evidence.

## Candidate disposition

C08's automatic-refresh **size-limit** explanation is unexposed in this complete
finite population. Automatic changed-delta delivery is exposed, sometimes followed by
further requested reads. C18/C29 recovery remains an observed cost and a potentially
mitigated cost, not a separately demonstrated contributor to the historical50% gap.
The three parser-error cases rule out treating the entire group as cross-agent conflict.

The remaining isolatable representation boundary is current full text versus the
delta from the same held previous/current snapshots at automatic refresh. It differs
from C02's requested repeat delivery. Such a factor must preserve actual rejection,
snapshot advancement, permissions and truthful guidance; disabling locking, accepting
a stale patch or manufacturing a conflict would test something else. This evidence
does not itself admit that run or supply its net result.

This is evidence-only documentation. No runtime, agent-facing workflow, saved benchmark
or measurement report is modified; no real-agent verification is needed for the index.
