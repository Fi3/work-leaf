then records their actual provisional commit and touched-file ownership.
`src/patch.rs::apply_with_locks` checks patch applicability, applies/stages it
and commits. `apply_edit_with_locks` computes exact-context edits, writes/stages
them and commits. Neither path compiles the resulting tree before acceptance.
The private preview registry gate is specific to the separately opted-in
preview experiment, not a general buildability test.

clause impose buildability through instructions. `render_patch_applied_prompt`
supplies the validation/DONE guidance. Therefore an exact benchmark-only policy
inverse need not invent a new publication engine. The existing v2 variant still
is not that inverse: it keeps buildable increments. A future joint adapter
would need the complete intended owned spans, isolated activation, rejection
tests, and actual native-input verification. No existing flag already proves
this qualified composite, and no historical runtime checkpoint is restored by
changing a policy string.
