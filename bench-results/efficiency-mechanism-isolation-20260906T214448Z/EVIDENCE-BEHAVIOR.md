# Stage B behavior evidence

This is an evidence pass for C10–C23 and C32 under [the candidate-first plan](PLAN-CANDIDATE-INVENTORY.md), not another source-only catalog or an admission. It uses completed P/S/W records in workflow-ID order. Parked R outcomes/costs are not analyzed; no provider runs, control runs, source changes, semantic relabeling or percentages belong to this artifact.

## Findings and disposition

The completed evidence establishes a concrete **WL overhead offset**: commentary before a clean reviewer verdict triggers a needless author-done/reviewer-recheck cycle. In all twelve W workflows, 52 accepted fix requests divide into 36 containing an explicit FINDINGS marker and 16 containing only an explicit NO_FINDINGS marker after commentary. There are no absent-marker or conflicting-marker requests in this census. Every one of the latter 16 cases receives exactly an author `@work-leaf done`, then an accepted recheck and exactly `NO_FINDINGS`, with no intervening tool/edit action in those two turns. The 36 FINDINGS-bearing requests remain genuine-marker cases; their semantic validity is not inferred from the marker alone.

These 16 detours produce **32 exact completed responses**. Their recorded usage sums to 3,063,601 input tokens, including 2,609,152 cached input, plus 5,015 output tokens, including 4,703 reasoning-output tokens: **3,068,616 raw tokens on the observed detour responses**. This is neither a whole-workflow contrast nor a claimed net saving after removing the detour; future state, scheduling and subsequent work could differ. It is an identified branch that generated charged work after an already-clean verdict. It must not be misclassified as a saving from evidence-only resolution.

The earlier cue and work-unit results remain tested-but-not-demonstrated at their declared scope. Other behavior candidates below have observed actions or source-backed hypotheses, but this pass does not promote any to a proven whole-workflow saving. The accepted historical endpoint is unchanged.

## Clean-review detour: exact source cause

[review.rs::has_no_findings](../../src/review.rs#L411) accepts only the first nonempty line. [cli.rs::review_commit_streaming_with_ids](../../src/cli.rs#L1187) processes the review through `process_agent_reply_streaming_result(..., Optional)`, retains the aggregate public reply, then applies that test before routing a fix and recheck. The saved Direct [review_is_clean](../efficiency-raw-token-pilot-20260906T185328Z/infrastructure/drivers/bench-three-features-direct-common#L1040) instead scans to the first standalone FINDINGS/NO_FINDINGS marker. This is an actual differential recognition rule, not an assumption about reviewer reuse.

The source condition explains these exact traces: the final reviewer message is clean, while earlier commentary makes the aggregate first line non-marker text. This identifies an offset against WL, not a cause of WL's historical reduction. No normal-WL parser is patched here.
