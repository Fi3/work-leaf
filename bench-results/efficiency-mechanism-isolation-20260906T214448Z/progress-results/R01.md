### A — publication/test-timing contract

A-on contains two owned instruction spans: (a) design tests first but submit
them with buildable implementation, explicitly superseding executed RED timing;
(b) submit cohesive implementation/tests when both are known.

A-off restores the original executed-test-first obligation: publish the new
tests through the same edit operation, run the relevant check to observe the
missing behavior/API before production implementation, then implement and rerun.
Actual failures and every required test remain. The second cohesive-publication
span becomes permission to publish the genuinely ready test/implementation unit;
it does not force arbitrary extra fragments, fake failures or busywork.

Crucial feasibility distinction: this standalone `Host.apply` validates
paths/old blocks and commits actual changes but does NOT run a buildability
gate before accepting them. A test-only intermediate commit is therefore
possible without changing the host, matcher, locks, command execution or C.
Normal concurrent WL's shared-buildable constraint is not silently weakened.
This is not W's incremental-but-buildable wording screen or C15's private
preview transport.

### B — result-bound next-action/completion/reporting guidance

B-on is the actual post-edit one-focused-check → DONE guidance (with genuine
remaining work/repair permitted), the command-result continuation/DONE suffix,
anti-restatement guidance, the corresponding launch one-GREEN clarification,
and the post-discard continuation reminder.

B-off removes those owned guidance spans together. Preserve the exact factual
accepted-file/provisional-commit prefix; actual command, status, stdout/stderr
and pending diffs; every rejection, repair permission, serialization rule,
operation grammar and ownership check. Preserve the general requirement to
complete the task and tests and the DONE marker's syntax. Do not require more
tests, longer reports or unnecessary work. Native commentary remains available;
structured host finals remain parseable. The instruction/feedback byte delta
itself is part of B and must be reported separately from downstream behavior.

Unlike V11, this starts a fresh qualified author episode. It does not fork an
all-on history, remove one fresh sentence after inheriting all other cues, or
silently accept extra developer reinjection as an isolated result.

### C — native write/tool availability and custody

C-on is read-only native inspection plus host-owned writes/commits and real
verification commands, with same-thread feedback between operations.
`invoke` hardcodes read-only and verifies `Host.unchanged` both before and
after the complete native invocation. Unexplained native edits are fatal.

C-off for the full A+B+C inverse uses the saved native-author execution boundary:
workspace-write native tools, original test-first author instructions and
native tool results; no standalone edit/check dispatcher or its after-operation
guidance. The driver retains uncommitted author work and owns the actual
post-author commit, as its original prompt states. Required task, tests,
focused-check scope, subscription/model and isolated base remain fixed.
Reusing that existing initial-author path is feasible without a new host.

A C-only toggle while B stays on is NOT qualified: enabling native writes
alone triggers `Host.unchanged`; accepting those writes only after the native
turn would deliver B's real commit/check feedback too late, after intervening
model decisions. A per-native-tool interception/commit bridge would be new
experimental machinery, not the approved existing boundary. No such bridge
is selected.
