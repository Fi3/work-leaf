# C08 recorded-response lower-only qualification

This separate, not-yet-admitted operation qualifies observed completed charges. It preserves all three original accounting results, workflow outcomes, source errors and missing usage. It supplies no corrected original result, cumulative-prefix verdict, upper-bound recovery, baseline ledger replay or percentage. All three candidate upper endpoints are null.

The fixed population is automatic-refresh-01 workflows 001/002/003 and the six W references already declared in `postcapture/ACCOUNTING-SCOPE.json`. Failed 001 and W010 remain included. Existing full maps supply all 123/296 records for 001/002. The complete original 003 response sidecar supplies its 275 records; those counts are source observations, not runtime special cases or totals. Expected counts belong to the future declaration.

## Minimal interfaces

`qualify(population, arithmetic)` accepts materialized objects for synthetic testing. `execute(scope_path, scope_sha256, output_path)` is the only source-bound entrypoint; its CLI has no alternate helper, auditor, model or population option. A new `work-leaf-c08-observed-lower-scope-v1` JSON declares:

- `execution_authorized`, `preparation` (the pinned `LOWER-BOUND-PREPARATION.md` bytes, not JSON), `accounting_scope`, `original_consolidation`, `arithmetic` (accounting and strict source references), `source_sha256` for direct additional inputs, and `output_path`.
- Three ordered `candidates`, each with `run_id`, `expected_response_count`, `original_full`, `original_projection`, `source_input` and `source_result` references. Only 003 also names `eligibility_input`, `eligibility_result` and `response_sidecar`.
- Baseline receipt/supplement references come only from the pinned original accounting scope, not a separately editable population list.

References are exact canonical regular-file path/SHA pairs. The loader unions the exact declared nested source maps and explicitly referenced source scopes, rejects conflicts, then verifies the finite union before numerical work and afterward. It never recursively discovers filesystem paths or rereads directories. Output and its `.ATTEMPT.json` are exclusive, separate from all inputs; a retained attempt prevents retry. Source failure prevents qualification, without editing any old output.

## Population proof

001/002 reuse their complete original `exact_response_evidence` maps, full canonical-result digest and projection identities. Each lower endpoint must equal the original recorded/corrected usage; these are consistency checks, not baseline arithmetic. Original source references and all diagnostics remain visible.

003 indexes all original sidecar records, all raw `rawResponse/completed` events and all explicit native `token_usage_record` rows. Their complete response-ID sets, typed thread/turn identities and four counters must match. Duplicate identical events count once; conflicting identity, unsupported cache-write scope or invalid counters reject. The sidecar's `valid` flag is insufficient. Its parsed-message sequence is checked against nonempty parsed server messages while physical source lines are retained separately.

Every recorded response belongs to the source-qualified accepted-input set and native source/thread/context set. A matching prior context is required unless the exact singleton saved eligibility proof binds the full response payload, native row sequence, original metadata, physical location and matching public response. That proof is consumed, never regenerated. Compaction is already a recorded response; no additional charge is appended. Native cumulative fields and observer `cumulative_mismatch` remain original evidence, not a new prefix assertion.

The input's `metadata_row_sha256` binds the original physical metadata line bytes; the proof's `native_metadata_sha256` separately binds canonical JSON with UTF-8 preserved. They need not be equal. Both identities are retained. Native blank lines retain `{}` for the historical proof hash; server blank lines use a distinct in-memory `None` sentinel so a literal `{}` remains a parsed message and advances the original sidecar sequence.

The corrected source receipt may retain only its declared ordinary `trace-occurrence-not-joined` errors. Frame, invocation-stream, native-membership and project subproofs must remain successful and source-bound to the same inputs and reviewed helper. Global exposure is not asserted.

001's extra accepted usage-less failed turn remains an unresolved coverage row. It is not a zero-charge response and cannot inherit a response-count ceiling from the three separate interrupted-tail proofs. The original three/five/24 gap populations and all unknown upper endpoints remain intact.

Six baseline projections are reused unchanged. Their complete supplement maps must match both saved count/canonical-hash projections. All nine response-ID maps must be disjoint. Baseline usage is not summed, re-extracted or re-audited; future fixed contrasts belong to the caller.

## Arithmetic and tests

Exact SHA-pinned AST definitions provide unchanged `accounting_untracked_reads.py::checked_usage/add` and their `batch_analysis.py::integer/usage` dependencies. No whole source loader, auditor, `corrected_ledger`, `reconcile_stream`, `prove_future_contexts`, observer, extractor or provider entrypoint is executed. Direct sums occur only after the finite response population passes.

Synthetic tests cover both old maps, singleton future context, repeated identities, missing/extra records, full source ownership, JSON types, physical blank lines, source drift, original/projection mismatches, all-nine disjointness, unknown outcomes, disarmed scope and exclusive publication. An actual study execution requires a new root-reviewed fixed-source declaration after the implementation gates close. No actual totals are calculated in development.

Indexing and validation are linear in source bytes and record count, apart from canonical key sorting. Sources are hashed once per endpoint rather than once per response. No response-by-source rescan or new quadratic join is intended. Closed-source endpoint checks do not prove hostile concurrent containment or hidden-provider completeness.

All nine maps and their disjointness pass before any candidate charge sum. A candidate failure leaves every candidate bound unavailable. Six baseline receipts remain retained even when a baseline validation fails. Output and attempt publication is exclusive and synced, not transactional: a failed result write can leave an incomplete output plus the permanent no-retry attempt.

The source interface accepts only explicit references and named nested `source_sha256` maps. It does not copy those maps repeatedly into new scope files. Limits are 20,000 source paths, 1 GiB/file, 32 GiB per endpoint pass and 32 MiB serialized result; these are admission/publication bounds, not a general peak-memory guarantee.
