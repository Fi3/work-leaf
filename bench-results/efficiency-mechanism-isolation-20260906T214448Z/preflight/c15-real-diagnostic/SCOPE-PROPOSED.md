# Private-test-first real-agent qualification scope

This is fixture preparation under the approved qualified C15 workflow, not a
provider admission or complete benchmark. Root owns this fixture and a later
create-new, source-frozen admission. Normal-WL controls, Direct workflows,
automatic retries and replacement observations are excluded.

## Qualification question

Can a real subscription-backed author propose its own regression test, receive
actual private preimplementation feedback, then publish a normal combined patch
and complete ordinary validation/review, without publishing the private RED tree
or changing ordinary acceptance, model settings or launch/follow-up semantics?

The private workflow includes its explicit feedback transport and private
environment/build state. It is not a pure timing intervention or token-effect
estimate. A natural first GREEN, malformed proposal, wrong command, unrelated
failure, timeout or delivery failure remains its actual outcome. No fixture
provides a prewritten test to guarantee RED.

## Avoid model-generated measurement bookkeeping

Live preview metadata identifies natural test purpose and normalized test paths,
alongside proposal identity/revision, format, reason, focused command and lock
paths. It does not ask the model to count UTF-8 offsets, supply hashes or repeat
test text inside metadata. The host retains the actual patch and exact declared
file after-images with byte lengths/hashes. This prospective transport refinement
prevents bookkeeping output/reasoning from masquerading as test-first cost.

Whole-file equality is not automatically assertion equality when production and
tests share a file. Same-test versus revised-test qualification uses exact held
and final source with an explicit source mapping; unsupported/ambiguous mappings
remain qualified. Internal provider-free RED-to-GREEN fixtures may use exact byte
ranges, but that bookkeeping is not part of the live model prompt.

## Small dependency-free project

The fresh owned project is a minimal Rust library with a supplied existing
`capped(value, limit)` function that returns `value` even when it exceeds `limit`.
The request is to return the smaller input and cover the regression, preserving
below-limit/equal-limit behavior. The author receives the complete tiny initial
source and manifest, not a test or implementation patch. It chooses actual test
content and uses the ordinary edit or unified-diff grammar.

The initial Cargo manifest/lock and source are committed before provider start.
Private builds use the separately pinned public toolchain/capsule through the
qualified bridge. No dependency download, credential copying, external state,
shared failing test-only commit or unsafe fallback is part of the fixture.
The natural focused command is the dependency-free crate's locked/offline Cargo
test. Any different actual command remains captured and checked against scope.

## Real workflow boundary

Author launch uses `CommandChat::prepare_agent_launch` followed by
`launch_prepared_agent_streaming`, so the actual private author ticket exists
before policy injection. No Agent-ID-name inference enrolls the author. An
ordinary `handle_line("review")` drives the reviewer; its policy and context are
not rewritten by the C15 treatment. Reviewer instructions are not placed in the
shared feature field as a separate forced diagnostic role script.

Expected chain: natural private test proposal → captured accepted source → closed
private execution → same-session factual result → ordinary combined shared patch
→ real applied ACK → normal focused validation → done → real review. Only a
delivered actual test result gates shared application; no private implementation
or extra private GREEN operation is exposed. Normal validation/review is the
authority for the accepted tree. All actual extra/revised work is retained.

One prospective attempt has an eight-outer-call ceiling, two intended real roles,
and a 240-second overall watchdog. These are bounds, not a requirement to fill
eight calls or permission to invent work. Final admission must freeze exact
limits after provider-free fixture testing and confirm they cover private-child
closure. The existing private-command maximum is not silently broadened.

## Gates and retained evidence

New fixture guard tests must fail before implementation and then cover its scope,
call ceiling, role path and terminal classification. Required repository gates,
private bridge/core review and actual-project private execution qualification
precede admission. An ignored real test is not verification.

The admission binds source/build/bridge/config/helper/public-tool identities,
fresh project/evidence roots, stored-subscription wrapper, observer settings and
exact output paths. Model/effort, raw usage, 1000-ms grace and output forwarding
remain the study's existing values. No API-key authentication or API credits.

Original process and checker outcomes are retained separately. Closed raw/public
and explicit native thread/turn/item evidence must match all accepted inputs,
actual preview identity/result, normal ACK/command/review exchanges and final
settled turns. Native action absence requires native inventory, not just absent
public tool events. Provider failure and metadata-publication defects remain
distinct. The final source review identifies the actual new test's failure and
unchanged or revised relationship to accepted tests; a nonzero exit alone is not
behavioral RED. No usage total or causal percentage follows from this diagnostic.
