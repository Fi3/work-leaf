# C15 full-workflow launch binding

The private launcher supplies the ordinary driver's dynamically allocated checkout
to the existing v6 runtime. It has no provider, preview execution, source capture,
shared patch, accounting or retry operation. The three admitted workflows all use
`private-test-first`; the six saved normal-WL observations remain external baseline
evidence, including failed010. The governing scope is
[PROTOCOL-TEST-FIRST-SCREEN.md](../../PROTOCOL-TEST-FIRST-SCREEN.md).

## Preparation and immutable identity

`runner_test_first.py` exact-compiles the pinned `runner_work_units.py` source into
a private module. Its overrides are the v6 condition, exact three-row screening
plan, supplemental dependency verification, and substitution at the engine's
specific experiment-file publication calls. No supervisor source text is rewritten.
The original scheduling, environments, admission marker, trust classifier, waits,
signals, outcome classification and closure code remain the engine's functions.

The CLI retains `plan`, `prepare`, `verify` and `run`. `prepare` takes the existing
engine arguments plus required `--bridge-config` and `--python`. It accepts the
qualified full-project CONFIG SHA `5e1e5a20…`, with private120/300-second bounds,
1-MiB retained output bound, exact ordinary instruction overlay and runtime mode.
It never substitutes the dependency-free diagnostic's empty-overlay configuration.

Before the engine publishes `PHASE-MANIFEST.json`, preparation creates:

- `launch-inputs/BRIDGE-CONFIG.json`, byte-identical to the qualified configuration;
- `launch-inputs/bind_daemon.py`, exact binding-helper bytes;
- `launch-inputs/work-leaf-orchestrator-real`, the native runtime ELF;
- `launch-inputs/driver-bin/work-leaf`, the unchanged native CLI;
- `launch-inputs/driver-bin/work-leaf-orchestrator`, the generated Python bootstrap;
- empty `private-preview/<run_id>` directories and a `launches` parent.

The engine copies the generated bootstrap and unchanged CLI into its normal
`infrastructure/bin` paths. Every launch input, executable, helper, configuration
and declared public capsule file is in the original manifest's checked file list.
Existing helper/toolchain/capsule paths remain individually hash-pinned external
inputs; the project is not confused with immutable input files. The engine still
hashes every manifest file at its normal boundaries. It does not pin private
results or later mutable project afterimages as immutable admission inputs.

`experiments/<run_id>.json` contains `work-leaf-c15-launch-template-v1`, expressly
not an active v6 manifest. The template names the run, condition, base, prompt
trace, runtime parent, private root, binding output root, Python/bridge/config/ELF
references, complete source-hash map and required ordinary environment subset.
The bootstrap embeds the exact template reference for each of the three run IDs.
Its helper bytes are verified before exact compilation; Python runs isolated and
without new bytecode. Phase names are at most67 characters so the suffixed run
identity fits the qualified bridge's80-character limit.

The ordinary driver retains its byte identity and existing daemon invocation.
`bench-three-features` creates `runtime/<allocated>/repo`, installs the standard
skip-worktree instruction overlay, initializes observation and invokes the shim in
that cwd. The shim does not create or install a shared overlay. The known `repo`
layout and sibling `tmp`/`context-bundles` checks belong to this pinned driver
adapter, not a new generic Work Leaf project convention.

## Binding and failure retention

The shim selects only its exact admitted run. It exclusively claims
`launches/<run_id>` and writes `ATTEMPT.json` before validating dynamic state.
An unknown run has no owned output location and fails without writing another
run's directory. A reused or aliased output root fails without overwriting it.
Once claimed, subsequent startup errors retain `ERROR.json` where publication is
possible. Partial failure is not permission to retry or clean the evidence root.

The binding verifies the actual canonical cwd, exact ordinary Git root/base,
accepted/index/live file census and full observed overlay flags using the existing
qualified live selector's read-only `census`. It does not call `capture_selection`,
materialize source, run a private command or assert the caller holds a WL lock.
The two equal startup censuses establish sampled endpoints before daemon startup,
not continuous or hostile-host atomicity. Private evidence is empty and separate
from both driver cleanup and ordinary bundle namespaces. The full bridge's existing
read-only configuration validator checks the pinned helper/capsule identities.

After those checks, `EXPERIMENT.json` contains the actual v6 manifest, with exact
project root plus the declared empty private root and unchanged Python/bridge/config
references. `BINDING.json` records its SHA, static template reference, real ELF,
observed wrapper identity, project census, all source hashes and complete input and
forwarded environment hashes. It records no environment values or credentials.
Arguments are hashed; the complete original argument vector is passed through.

Only `WORK_LEAF_BENCH_EXPERIMENT_MANIFEST` changes in the daemon environment: it
points from the immutable template to the new actual manifest. Every other value,
including provider wrappers, observation settings and original `CODEX_HOME`, is
passed through without alteration. The wrapper then `execve`s the real pinned ELF
with the original argument vector and standard streams, without an extra daemon
child or a new process group. The driver remains the terminal-outcome authority.

`BINDING.json.status=ready_for_exec` does not assert successful exec, provider work,
or a qualified preview. A failed exec retains that receipt and a separate error.
Publication is create-new, fsynced and read back, but not a multi-file transaction.
Source endpoint hashes are checked before execution; these are non-hostile
single-operator safeguards, not descriptor-exec containment of adversarial races.

The driver's `runner-bin/work-leaf-orchestrator` copy is the shim. The separately
retained `launch-inputs/work-leaf-orchestrator-real` is the actual runtime ELF;
postcapture source proof must join both instead of calling the shim the runtime.
Private results and binding records survive normal temporary-checkout cleanup.

## Verification and limits

Automatic tests use synthetic preparation, fake exec callbacks, real read-only
Git/overlay checks and one actual generated-bootstrap invocation of `/usr/bin/true`.
They call no provider or private executor. No test supplies agent-authored tests
or changes the benchmark's feature prompts. Startup source work is a fixed number
of linear hashing/census passes, plus existing dependency validation and Git work.
The unchanged engine retains its documented O(W×E) checks; this plan fixes W=1,N=3.
The bridge retains its documented capsule-directory/path and predecessor complexity
limits; the binding does not introduce a pairwise event or workflow scan.

The existing C15 runtime's real verification is diagnostic003. Real verification
of this new daemon binding is still required at the first admitted full workflow;
the `/usr/bin/true` fixture is not real-agent evidence. A failed first binding is
a retained benchmark outcome, never authorization for another diagnostic or a
replacement observation. Original observer flags and unsupported token tails
remain separate gates; this adapter does not alter them.
