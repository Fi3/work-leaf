# Carry diagnostic publication

`accounting_carry_publication.py` is a future-use, analysis-only sibling of the immutable `accounting_compaction_carry.py`. Its only difference is ownership of published diagnostics. A context proof can load auxiliary accounting modules without using their reconciler; the module whose instrumented reconciler actually executes remains the diagnostic owner.

The sibling exact-compiles predecessor SHA `47d28ef42c3243344cb28d6db680a531b04255cdc310653e45fc3ee81b8418a1`. Three singleton source seams retain loaded states, select the unique actually invoked state, and fail closed when multiple accounting modules reconcile captures. A never-used module cannot displace the owner. No invoked module leaves the original unavailable/unknown result intact. Partial capture census remains explicitly partial. The original reconciliation, native model-context proof, cumulative arithmetic, warning/tail rules and strict-accounting code are unchanged.

## Interface and identity

The callable remains `audit_run(entry, frozen, sessions_root)`; there is no provider or numerical-admission CLI. Its future use requires a separately declared numerical scope, caller-verified source/dependency identities and all original delivery/configuration/source gates. The new callable has not been run against any saved workflow.

Callers compile the admitted source bytes with the actual absolute `__file__`, not cached bytecode. The sibling binds the loaded predecessor bytes at import and rechecks them before execution and at closure. It retains predecessor provenance and adds `diagnostic_publication_derivative` with its own source SHA and the exact executed publication-wrapper SHA. A source mutation makes the result unknown. The sibling does not replace existing helper files, receipt fields, outcomes or recorded canonical full-result hashes.

## Qualification and complexity

Eight new synthetic tests cover auxiliary loads before/after the owner, an owner that is not first, multiple used modules, partial-census failure preservation, the retained predecessor bug, no-aux full-result identity, loaded-source drift and unlaunched unknown results. The initial regression ran against the unchanged predecessor and failed before the sibling implementation. The validation receipt records exact commands and hashes.

Owner selection is one O(L) scan over loaded states. Retaining wrappers holds O(L × D) dependency state for L loaded modules and dependency size D. This is a documented memory cost, not an event-pair scan; no O(E²) accounting pass is introduced. The predecessor's event/byte complexity remains unchanged.

No real-agent workflow is affected: only offline diagnostic publication differs, and no provider, runtime, observer, prompt, wait, configuration or public Rust API is touched. Real-provider verification is not applicable. Existing frozen reports/helpers/tests remain immutable.
