# Optional Follow-Up Work

## Current Decision

The present study answers the immediate product question for the frozen three-feature Rust
benchmark. No additional paid run is required to establish the observed saving or its dominant
workflow source.

Further work should start only when one of the narrower goals below matters.

## More Precise Percentages

Run additional independent direct sequential and normal concurrent Work Leaf observations under one
frozen CLI and randomized launch order. Decide a practical stopping rule before launch. Use group
means rather than fixed pairs, retain every quality outcome, and report quality jointly with tokens.

This improves precision for the overall saving. It does not separate the remaining Work Leaf
mechanisms.

## Exact Allocation Inside The Remaining Workflow

The current evidence groups structured edits, write-command mediation, focused concurrent
validation, exact review targeting, and compact linearization together. Separating them requires new
experimental controls because the production CLI has no switch that independently disables each
behavior.

The smallest useful controls would be:

1. A benchmark-only patch-agent mode with direct writes and direct write-producing commands while
   preserving Work Leaf scheduling, review, task text, and final checks.
2. A benchmark-only linearizer mode that receives the full uncompressed workflow history instead of
   the normal compact reviewed target.

Both controls alter Work Leaf behavior or prompts. They require explicit authorization, tests, an
isolated build, and a fresh fairness audit before any provider launch. Existing results must remain
immutable.

## Statistical Confidence

Predeclare the number of runs or a realistic interval target, then collect in short batches of three
concurrent workflows. Stop after each batch to verify accounting, model identity, quality, and
artifact integrity. Do not use an impractically strict percentage-point equivalence target to derive
thousands of workflows.

## Other Repositories

Repeat the frozen endpoint comparison in at least one unrelated Rust repository and one project
with a different toolchain. This tests whether the workflow-batching advantage is general or depends
on this repository's overlapping UI/controller features.
